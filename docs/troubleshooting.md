# PaddleOCR PP-OCRv5 常见坑排查

## 1. 安装慢或下载失败

现象：

```text
pip install paddleocr 很慢
模型首次推理下载失败
```

处理：

- 换稳定网络。
- 使用国内 pip 镜像。
- 手动下载模型后指定本地模型目录。
- 留意代理环境变量是否影响下载。

## 2. PaddlePaddle 和 CUDA 不匹配

现象：

```text
paddle.device.is_compiled_with_cuda() 返回 False
或运行时报 CUDA/cuDNN 相关错误
```

处理：

- 先用 CPU 跑通流程。
- 用 `nvidia-smi` 查看驱动。
- 到 PaddlePaddle 官方安装选择器选择准确命令。
- 不要随便混装多个 CUDA 版本的 wheel。

## 3. Windows 路径问题

现象：

```text
FileNotFoundError
YAML 路径解析异常
```

处理：

- YAML 里优先用 `/`。
- 绝对路径写成 `E:/Git_repo/...`。
- 标签文件里的图片路径相对 `data_dir`。

## 4. 训练数据格式错误

检测标签示例：

```text
images/demo.jpg	[{"transcription":"文字","points":[[10,20],[100,20],[100,50],[10,50]]}]
```

识别标签示例：

```text
images/crop_001.jpg	文字
```

不要把整图检测标签拿去训练识别模型，也不要把裁剪图识别标签拿去训练检测模型。

## 5. 字典不匹配

现象：

```text
识别训练报字符错误
训练能跑但准确率很差
导出后推理乱码或错字多
```

处理：

- 扫描训练/验证标签所有字符。
- 确保每个字符都在 `dict.txt`。
- 训练、导出、推理使用同一份字典。
- 有空格就确认 `use_space_char: true`。

## 6. 显存不足

现象：

```text
Out of memory
ResourceExhaustedError
```

处理：

- batch size 减半。
- 先用 mobile 模型。
- 降低输入尺寸，谨慎改配置。
- 先用小样本确认流程。

## 7. loss 降了但真实图片效果不好

原因可能是：

- 验证集太简单。
- 标注质量差。
- 训练数据和真实数据分布不同。
- 只训练识别，但实际是检测框错。

处理：

- 固定一批真实业务图片作为回归测试集。
- 每轮训练后保存 JSON，对比错误样本。
- 把失败样本补进下一轮训练集。

## 8. 检测框效果差

重点检查：

- 是否漏标。
- 框是否太松或太紧。
- 多行文字是否标注规则一致。
- 图片缩放、旋转、增强是否过强。

## 9. 识别准确率不升

重点检查：

- 裁剪图是否真的只包含一行文字。
- 标签是否错字。
- 字典是否覆盖所有字符。
- `max_text_length` 是否太小。
- 是否需要更多同类样本。

## 10. 自训练模型推理失败

重点检查：

- 是否用 `export_model.py` 导出了 inference 模型。
- 推理路径是否指向导出目录，而不是训练 checkpoint 目录。
- 识别模型是否传了同一份字典。
- 检测模型和识别模型版本是否混搭过度。
